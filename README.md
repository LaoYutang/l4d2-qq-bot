# L4D2 QQ Bot

独立运行的 L4D2 QQ 官方机器人，支持服务器查询、玩家列表、黑盒语音和服务器管理。默认使用带连接按钮的 QQ 原生卡片回复，提供网页配置界面。

## Docker 镜像启动

新建 `.env` 文件，填写 QQ 机器人凭据和配置页密码：

```dotenv
L4D2_APP_ID=你的AppID
L4D2_CLIENT_SECRET=你的AppSecret
L4D2_WEB_PASSWORD=请替换为配置页密码
```

直接拉取镜像并启动，无需下载源码或本地构建：

```bash
docker pull laoyutang/l4d2-qq-bot:latest
docker run -d --name l4d2-qq-bot \
  --init --restart unless-stopped \
  --env-file .env \
  -e L4D2_CONFIG_PATH=/app/data/config.json \
  -p 8080:8080 \
  -v l4d2-qq-bot-data:/app/data \
  --read-only --tmpfs /tmp:rw,noexec,nosuid,size=16m \
  laoyutang/l4d2-qq-bot:latest
```

配置保存在 `l4d2-qq-bot-data` 数据卷中，重建容器后保留。需要固定版本时，将 `latest` 替换为已发布的版本号。Compose 部署、源码构建和升级方法见 [部署文档](docs/deployment.md)。

镜像默认以 root 运行。Sealos 部署时将可写持久化存储挂载到 `/app/data`，使用镜像默认启动方式即可，详见 [Sealos 部署说明](docs/deployment.md#sealos-持久化存储)。

## 首次配置

1. 打开 `http://服务器地址:8080/`，使用 `.env` 中的配置页密码登录。
2. 将机器人加入群，发送 `获取群ID`，在配置页添加返回的群 OpenID 和服务器。
3. 在已配置的群中发送 `获取用户ID` 获取自己的成员 OpenID，或发送 `获取用户ID @某人` 获取指定成员的 OpenID，将结果加入管理员列表，即可使用管理指令。

指令中的 `id` 不区分大小写，`ID` / `Id` / `iD` 均可。查询他人时，请使用 QQ 的 @ 功能选择一位成员，不要只手打 `@昵称` 或 QQ 号。未开启“接收所有消息”时，发送 `@机器人 获取用户ID @某人`。如果 QQ 未提供可识别的成员信息，机器人会提示让对方自行发送 `获取用户ID`，不会改为返回发送者的 ID。

服务器、管理员、连接地址和语音入口都可在配置页设置，保存后立即生效，无需手动创建 `config.json`。顶部操作栏随滚动保持可见，方便随时保存或重新载入。密码错误过多时，页面会提示等待后重试。

群主在 QQ 端开启“接收所有消息”后可直接发指令，否则需要 @机器人。群和成员必须使用机器人返回的 OpenID，不能填写普通群号或 QQ 号。

## 常用指令

| 指令 | 功能 |
| --- | --- |
| `获取用户ID` / `获取用户ID @某人` | 获取自己 / 指定成员的 OpenID，仅限已配置群 |
| `查询1服` / `查询 合作服` | 查询地图、人数、玩家和在线时长，附游戏及已配置的语音入口 |
| `综合查询` | 查看本群全部服务器状态，各服人数前带 👥，人数与地图保持紧凑列表 |
| `服务器列表` / `服务器地址` / `连接指令` | 正文显示各服名称与游戏地址，下方保留连接按钮，每行最多 2 个；无链接时显示连接指令 |
| `connect IP:端口` | 临时查询服务器，地址与状态使用同一引用块，默认仅允许公网地址 |
| `语音1服` / `查询1服语音` / `1服语音` | 查询黑盒语音频道人数，成员以紧凑无序列表展示 |
| `设置1服 status` | 管理员直接执行 RCON 指令 |
| `重启1服` | 管理员重启服务器，需在 30 秒内回复“确认” |
| QQ 闪传链接 | 管理员选择服务器和文件，提交地图下载任务 |
| `帮助` | 查看指令列表 |

“1服”等名称由配置页设置；语音查询需要配置黑盒凭据和频道，管理指令需要配置对应服务器的密码或面板凭据。

单服原生卡片的玩家姓名与在线时长使用 Markdown 引用块；零玩家、名单获取失败和未返回玩家名称分别提示。综合卡末页附有人服务器快捷查询按钮和独立一行“再次查询”，单服（含离线）末页保留连接入口并附“🌐 综合查询”“🔍 再次查询”。按钮发送普通文字“综合查询”或该服的查询指令，不带斜杠或按钮 emoji；采用指令按钮（type=2、enter=true），不新增回调。连接按钮开关同时控制这些查询按钮；图片模式维持原有流程。

综合查询只为查询成功且人数大于 0 的服务器提供快捷按钮，按原配置顺序、每行 2 个；末行“再次查询”发送“综合查询”，不加 emoji。为保留独立刷新行，快捷按钮最多显示 8 台，超出时正文会明确提示其余服务器请手动查询，完整状态结果继续保留。单服按钮仍显示“🌐 综合查询”“🔍 再次查询”。

同群、同成员、同一查询目标在查询进行中及结束后 2 秒内的重复群消息不会再次查询或回复；别名与名称解析到同一服时共享保护，不影响其他成员、目标或管理指令。QQ 官方文档对群聊 enter 自动发送的范围存在矛盾，真实客户端是否一键发送尚待联调；不支持时仍可手动发送按钮上的查询指令。

RCON 多包响应先合并为完整结果，再遮蔽服务器密码。完整脱敏回复不超过 200 个字符时发送一条文字；超过时只发送一个 UTF-8 `rcon-result.txt` 文件卡片。按 Python `len` 统计 Unicode 字符数，中文每字计 1，结果前缀、空格和换行也计入；不再连续拆发长文本。上传或发送失败会给出简短说明，不重新执行 RCON。普通查询与 Markdown 卡片保持原有分页。

查询卡片标题只显示服务器名；已保存服务器和临时查询都在顶部显示游戏连接地址，在线时与地图、人数、延迟放在同一个引用块，离线及文字回退也保留地址。在线玩家使用引用块展示，底部提供“🎮 进入服务器”和已配置的“🎧 进入语音”按钮。

## 本地运行

需要 Python 3.12+ 和 [uv](https://docs.astral.sh/uv/)。在项目目录填写同样的 `.env` 后运行：

```bash
uv sync --frozen --group dev
uv run l4d2-qq-bot run
```
